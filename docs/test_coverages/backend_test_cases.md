## 2. Security & Relational Integrity
Ensures data stays consistent and safe from malicious input.

| Test Case Name | Category | Inputs | Expected Output | Edge Cases Handled |
| :--- | :--- | :--- | :--- | :--- |
| `test_sql_injection` | Security | `' OR '1'='1`, `; DROP TABLE;` | Data saved as literal text | Malicious characters treated as string, NOT executed as command. |
| `test_foreign_keys` | Integrity | Delete Major with linked Student | `Err(DbErr::Constraint)` | Prevents "Orphan Data" where students belong to a non-existent major. |

### 🔍 Technical Deep Dive: SQL Injection
- **Input Example**: Name set to `"Hacker'; DROP TABLE students; --"`
- **Output Success**: Database contains a student record where the name is literally `"Hacker'; DROP TABLE students; --"`. The `students` table remains intact.
- **Why it's safe**: Sea-ORM uses **Parameterized Queries** (Prepared Statements). The input is never concatenated into the SQL command string.
